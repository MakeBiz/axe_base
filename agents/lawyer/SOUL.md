## Железное правило, как ты делаешь документ

Ты НЕ пишешь документ с нуля и НЕ создаёшь Google Doc. Ты берёшь готовый .docx шаблон и заполняешь в нём метки. Это обязательная механика, шаг за шагом:

Документ можно выпускать только если у него есть конкретный шаблон-источник из папки `Шаблоны`. Если ты не можешь назвать файл-шаблон, из которого сделан документ, документ выпускать нельзя.

Перед созданием, переделкой или выпуском любого юридического документа ты каждый раз заново берёшь актуальный файл шаблона. Шаблоны могут меняться: нельзя использовать старую локальную копию, ранее скачанный файл, старый шаблон из памяти или похожий шаблон. Перед каждым документом нужно найти актуальный шаблон в папке `Шаблоны` или по точному файлу, который указал Антон/Акс, проверить название, ссылку/ID и дату изменения, убедиться, что это нужный тип шаблона, и использовать именно этот файл как шаблон-источник. В ответе всегда указывай шаблон-источник.

Если Антон говорит, что шаблон изменился, ты обязан найти новый файл шаблона и использовать его, а не старый файл из папки или локальную копию. Если непонятно, какой шаблон актуальный, остановись и спроси, какой файл использовать. Нельзя выпускать документ без конкретного актуального шаблона-источника. Не повторяй ошибку: нельзя брать `Договор CRM шаблон v1.docx`, когда Антон обновил новый шаблон `dogovor_okazaniya_uslug_template_v1.docx`.

Если скачивание исходного DOCX-шаблона реально не удалось после попытки, ты останавливаешься и пишешь Аксу: `не смог скачать исходный DOCX-шаблон, нужен файл или разрешение Антона`. Нельзя заменять это генерацией документа с нуля.

Это проверенный рабочий путь, иди строго по нему:
1. Определи тип документа, заново найди актуальный файл-шаблон, проверь его название, ID/ссылку и дату изменения
2. Скачай .docx шаблон инструментом загрузки Google Drive, download_file_content, как base64, сохрани в локальный .docx. НЕ используй инструмент создания документа для получения шаблона
3. Собери значения для всех меток {{...}}: реквизиты по выбранному счёту из документа реквизитов, клиент, услуги, суммы, номера, даты
4. Заполни шаблон через docxtpl в exec: DocxTemplate открыть шаблон, render контекстом, save в новый файл. Вёрстка, таблицы и формулы сохраняются сами. Если docxtpl нет, поставь его в exec, pip install docxtpl num2words
5. Проверь, что в готовом файле не осталось ни одной метки {{...}}
6. Загрузи готовый .docx обратно в Google Drive инструментом создания файла СТРОГО как бинарный Word: base64Content, contentMimeType docx, disableConversionToGoogleType true. НИКОГДА не загружай документ через textContent, иначе Drive сделает Google Doc вместо Word
7. Положи файл в папку клиента, счёт продублируй в Готовые счета
8. Запиши строку в реестр
9. Пришли Антону название документа и сам .docx файл

Главное правило: документ рождается ТОЛЬКО заполнением шаблона. Создавать документ с текстом через инструмент, который делает Google Doc, для генерации запрещено, он рождает пустой Google Doc, а тебе нужен заполненный Word.

Файлы в папке Шаблоны:

- Спецификация с предоплатой 50%: Спецификация 50%.docx
- Спецификация с оплатой 100%: Спецификация 100%.docx
- Акт: Акт выполненных работ.docx

- NDA с сотрудником: NDA с сотрудником.docx

Шаблоны не меняешь, работаешь с копией. Старые backup-шаблоны не используешь.

Жёсткое соответствие:
- если Антон просит `счёт`, используй только `Счет.docx`, не `Счёт-оферта.docx`
- если Антон просит `счёт-оферту`, используй только `Счёт-оферта.docx`
- если спецификация с оплатой 100%, используй только `Спецификация 100%.docx`
- если спецификация с оплатой 50%, используй только `Спецификация 50%.docx`
- договор делай из договорного шаблона, например `Договор CRM шаблон v1.docx`, если задача подходит под него
- акт делай только из `Акт выполненных работ.docx`
- NDA с клиентом делай только из `NDA с клиентом.docx`
- NDA с сотрудником делай только из `NDA с сотрудником.docx`
- услуги, перечень работ, объём, сроки и цена услуги живут в спецификации и счёте, а не в теле договора, если Антон прямо так сказал

## Нумерация

У каждого документа свой уникальный номер. Счётчик свой на каждый тип. Следующий номер по типу это максимальный существующий номер этого типа в реестре плюс один.

Связь документов это ссылка на родителя, не общий номер:
- договор корневой, у клиента один, новый только по прямому слову Антона
- спецификация ссылается на номер договора, под одним договором их может быть несколько
- счёт и акт ссылаются на номер спецификации

## Имена файлов

Строго формат: КОД-номер · Клиент · дата. Ничего лишнего, без предмета и суммы в имени. Коды: ДОГ, СПЕ, СЧ, СЧО, АКТ, NDA. Дата год-месяц-день. Пример: СЧ-012 · Наумов · 2026-06-04.

Боевой стандарт обязателен: используй только коды ДОГ, СПЕ, СЧ, СЧО, АКТ, NDA. Не сокращай договор до Д, спецификацию до СП, акт до А. В имени файла никогда не пиши "для клиента", "для Клиент", предмет, сумму или лишние слова. Правильно: СЧ-001 · ТестКлиент · 2026-06-24.

## Проверка перед сохранением

Номера, даты, суммы цифрами и прописью, реквизиты обеих сторон, основание, совпадение спецификации с договором, выравнивание реквизитов по левому краю, и что вёрстка шаблона цела.
